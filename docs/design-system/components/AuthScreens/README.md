Sign in, create account and password reset. **Design only**: customer accounts are not specified yet (identity specs cover staff only; customer accounts are a later sprint), and the lockout rule (FR-39 hard lockout vs SEC-02 throttling and CAPTCHA) is an open decision, so the locked-out state is not drawn.

- **Layout.** A slim header (wordmark only). On desktop a split: a full-height photograph with one line on the scrim on the left, the form on the right; on a phone the form alone. One `<h1>` per screen, one marigold button per screen.
- **Sign in.** Email, password with a Show/Hide button (`rp-pw`), "Keep me signed in", "Forgot password?", **Sign in**, and "New here? Create an account". The error variant shows a notice ("We could not sign you in") and a field error under the email with an icon and an instruction; focus moves to the notice.
- **Create account.** First and last name, email, mobile number (used for delivery updates), password with a placeholder for the rules, a required Terms and Privacy checkbox and an optional newsletter checkbox.
- **Reset.** Request (email, **Send reset link**), **Check your email** (says "If an account exists for that email address, a reset link is on its way", so it never reveals whether an account exists; resend with a cooldown), and **Set a new password** (new and confirm; "Link expired? Request a new one").

Rules: every control has a visible label, `autocomplete` values are set (`current-password`, `new-password`, `email`, `tel`), errors state what to do next, and a failed sign-in never says which of email or password was wrong. Never log passwords (SEC-25). These pages are `noindex` and blocked in `robots.txt` (SEO-05). Placeholders: password rules, link lifetime and resend cooldown. Not drawn: email verification, the locked-out state, sign-up and reset error states.
