## C. Images

16. [x] Pin SkiaSharp in `Directory.Packages.props` (licence noted); `IImageResizer` port with fake. Proof: build with warnings as errors. *Pinned SkiaSharp and SkiaSharp.NativeAssets.Linux.NoDependencies 3.119.2 (MIT). Beyond the task: `SkiaImageResizer` (the real adapter) is built and tested here, with `Probe` (header read, pixel cap) and `Resize`; task 17 wires it into the worker. Note for 17: `IFileStorage.SaveAsync` generates its own key, so writing a derivative under its hashed name needs a named-write method on the storage port.*
17. [x] `ProcessDerivativeJob`: `SKIP LOCKED` claim, decode caps (`MaxImagePixels`), metadata stripped, WebP + JPEG at configured widths, temp key then rename, retry with backoff, then `IMG_RDY_IND`. Proof: worker tests with fake resizer and storage; one real-resizer test in the Linux container (PCT-7). *Built: `ProcessDerivativeCommand` (one derivative per call, claimed with `FOR UPDATE SKIP LOCKED` in the command's transaction; rejection is permanent, IO errors retry with a doubling backoff up to `MaxDerivativeAttempts`, then failed; the product's `ImageReady` is recomputed on done or failed) and `DerivativeWorker` (drains, then sleeps `ImageWorkerPollInterval`; off with `Storefront:ImageWorkerEnabled=false`). `IFileStorage.SaveNamedAsync` is the named write (temp file, atomic rename, bare-name check). New `Storefront:` settings: `MaxImagePixels`, `ImageQuality`, `MaxDerivativeAttempts`, `DerivativeRetryDelay`. The real-resizer test is `SkiaImageResizerTests` from task 16.*
18. [x] Changed image gets new hashed names; `SweepDerivativesJob` removes unreferenced files after the cache lifetime. Proof: tests (PCT-10). *Built: new names came with task 17 (`ProcessDerivativeTests` covers the changed image). `SweepDerivativesCommand` lists storage (new `IFileStorage.ListAsync`), considers only keys that parse as derivative names, and deletes those no `IMG_DRV.FILE_KEY` references and older than `Storefront:DerivativeCacheLifetime` (default 30 days, not set by the spec). `DerivativeSweepWorker` runs it every `Storefront:DerivativeSweepInterval` (daily) and is off with `ImageWorkerEnabled=false`.*
19. [x] Readiness check reports failed-derivative count without failing. Proof: health test. *Built: `DerivativeHealthCheck` (tag `ready`) returns Healthy with none, Degraded with `failedDerivatives` in its data otherwise (`/health/ready` still answers 200), and Degraded rather than Unhealthy if the count cannot be read. The count is in the check data, not in the plain-text `/health/ready` body.*
